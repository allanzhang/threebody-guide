## 一、定位

**一句话定位**：面向没读过《三体》的人，顺着时间线读完整个故事；给读过的人，一份概念与人物都能查的全景图鉴。

**目标用户**：两栖打底——以路人（没读过小说的读者/观众）为主目标，以读者（读过三部曲、想系统梳理的粉丝）为次目标。路人走时间线建立框架，读者钻概念册速查深度内容。

**剧透策略**：全剧透定调。整体分析透彻三体故事在讲些什么，概念、人物、事件全量叙述、不折叠、不设防。

**产品形态**：纯静态内容站，一本「三体世界图鉴」——以天文尺度与科学符号为视觉语言的大幅排版画册，非交互式应用。

## 二、关键决策记录

1. **内容口径（纯小说正史）**：以刘慈欣《三体》三部曲为唯一事实源和世界观来源；不收录、不对照影视改编（腾讯剧版、奈飞、动画均不作主体内容）。数据模型预留「出处」字段与灰底注解机制，未来必要处可标注差异。
2. **图片素材（腾讯剧版为主 + 占位兜底）**：第一部可对应的角色/场景使用腾讯剧版剧照与海报（人物名字与小说一致、还原度高，认知负担最小）；无影视化内容的角色与场面（罗辑、章北海、程心、云天明、二向箔、威慑纪元等约占全站 2/3）使用科学符号风 SVG 概念占位图；占位图按「同名文件」输出，未来接真实素材同名替换即可。图片版权：个人非商用引用宣传剧照风险较低，站点底部加来源声明。
3. **信息架构（三线结构）**：时间线为主轴（顺着读懂故事）→ 概念册为第二核心（三体魅力所在：法则理论/科技器物/组织文明）→ 人物墙为第三层（深度内容承载）。三者 id 互链打通。
4. **时间线分章（纪元年表 + 所属书徽标）**：篇章按小说纪元年表切分——红岸与危机 → 威慑纪元 → 广播纪元 → 掩体纪元 → 银河纪元与归零（5 章）；每个时间线条目另挂「所属书」徽标（《三体》《黑暗森林》《死神永生》），让观众知道这段故事发生在哪本书。书是定位标签，纪元是叙事节奏。
5. **概念页双区块（书里怎么讲 / 科学底子）**：每个概念详情页固定两块——「书里怎么讲」（设定 + 剧情中如何登场使用）+「科学底子」（真实科学对应物 vs 文学发挥）。科学底子做通俗科普、点到为止、不较真：明确区分「真实科学 / 科幻假设」，说不清的明说「此为科幻假设」，不把文学作品当科学论文审。
6. **内容范围（全三部曲一次成型）**：M1 一次做完全三部曲全量——时间线条目（全部纪元）、概念册 30–40 个、人物墙 15–25 人。三部曲是不可分割的整体，第一部悬念须到二三部才闭环，最小自洽故事即全三部曲。
7. **技术形态**：纯静态网站。Astro 静态生成 + JSON 数据源 + 手写 CSS，零客户端 JS、零动态效果。部署 Vercel / Cloudflare Pages / GitHub Pages（base 路径 helper 化）。
8. **视觉基调（C 科学符号风）**：宽屏制作（最大宽度 1440px，头图允许全屏宽）。视觉语言用天文尺度与科学符号——大字号坐标数字、星图、无线电波形、等宽字体纪年；主色深空黑 + 冷白 + 红岸苍黄；每纪元一套主题色，形成「翻章换幕」节奏。排版上大字号、大留白，震撼来自幅面而非动效。

## 四、页面设计

### 4.1 首页

全屏 hero：站名「三体世界图鉴」+ 一句话定位 + 三个入口大卡（时间线 / 概念册 / 人物墙）+「这是什么」说明段 +底部「从哪开始读」三步指引（先读时间线建立框架 → 遇到概念点进概念册 → 遇到人物点进人物墙）。纯排版，无动效。

### 4.2 时间线页（核心页面）

**整体布局**：纵向长卷式，宽屏（最大 1440px），中央贯穿细线为时间轴脊，条目挂轴排列。

**纪元篇章结构**：

- 全站按纪元年表分 5 章：红岸与危机 → 威慑纪元 → 广播纪元 → 掩体纪元 → 银河纪元与归零。
- 每章开篇为全宽（100vw）头图（科学符号风 SVG 占位图），高度 60–70vh，大标题 + 3–4 行导读（路人视角讲清这个时代发生了什么、为什么重要）。
- 每章一套主题色（见视觉系统），章内时间轴脊、纪年大字、注解框跟随换色。
- 起始纪年用 200px+ 描边大字做背景装饰层（如「1969」「2208」「2270」），压内容后形成杂志封面层次感。

**时间线条目（常规）**：

1. 剧情纪年标记 — 大字号等宽字体视觉锚点（如「危机纪元 205 年」）
2. **所属书徽标** — 《三体》《黑暗森林》《死神永生》，位置明显不喧宾夺主
3. 条目标题 + 副标题（如「红岸基地 · 一切从哪里开始」）
4. 剧情梗概 — 150–250 字，讲清发生了什么、和前后剧情的因果
5. 关联人物行 — 可点击跳人物详情页
6. 关联概念行 — 可点击跳概念详情页（如「黑暗森林法则」「二向箔」）
7. 名场面图 — 腾讯剧照（第一部可对应者）或科学符号风占位图
8. 灰底注解框 — 原文出处/剧版差异等必要注脚（预留机制）

**时间线条目（大事件特别版）**：古筝行动、面壁计划启动、黑暗森林威慑、引力波广播、二向箔打击、归零等关键节点升级为全宽特别条目——图横铺、超大片名、梗概加倍详细（「整体分析透彻」要求的分析向内容在此展开）。

### 4.3 概念册页

**布局**：宽屏网格卡片墙，分组纵向呈现（不做筛选交互）：

1. **法则与理论** — 黑暗森林法则、猜疑链、技术爆炸、降维打击、归零、恒纪元/乱纪元、三体问题……
2. **科技与器物** — 智子、水滴、二向箔、曲率驱动、光速飞船、引力波广播、红岸基地、三体游戏、人列计算机……
3. **组织与文明** — ETO 地球三体组织、面壁者、星舰地球、三体文明、歌者文明、归零者、人类文明……

卡片内容：概念名 + 一句话定位标签（如「黑暗森林法则 / 宇宙社会学公理」）。预估 30–40 个。

### 4.4 概念详情页

**结构**：全宽头图 + 大字概念名，正文固定双区块：

- **书里怎么讲** — 该概念在小说中的设定、运作机制、在剧情哪里登场、对故事走向的作用（150–300 字，路人视角白话）
- **科学底子** — 真实科学对应物是什么、科幻发挥在哪；通俗科普、不较真；说不清明说「此为科幻假设」

底部：关联人物、关联事件（跳时间线锚点）、关联概念（互链）。

### 4.5 人物墙页

**布局**：宽屏分组网格，卡片 = 肖像（腾讯剧照或占位）+ 姓名 + 身份标签。

分组建议：红岸与源头（叶文洁、汪淼、史强……）/ 面壁与执剑（罗辑、章北海、程心、云天明……）/ ETO 与三体侧（申玉菲、潘寒、三体人……）/ 重要配角。核心人物（叶文洁、罗辑、章北海、程心、云天明）给双倍尺寸大卡。

### 4.6 人物详情页

**结构**：全宽头图 + 大字姓名，下方四段式：

- **他是谁** — 身份、背景、性格特质（150–200 字，路人视角白话）
- **他的作用** — 在整个三部曲中承担的叙事角色
- **他的故事线** — 按时间线叙述其出场与剧情走向，关联事件可跳回时间线锚点
- **关键抉择** — 分析向内容（罗辑的威慑、程心的两次选择、章北海的叛逃、云天明童话等），呼应「整体分析透彻」定位

## 五、视觉系统

- **主色**：深空黑底（约 `#0a0e14`）+ 冷白正文（约 `#e8e6e1`）+ 红岸苍黄点缀（约 `#b8a877`，呼应红岸基地/电波/警告色）。
- **章主题色**（可微调）：
  - 红岸与危机：苍黄锈红
  - 威慑纪元：冷蓝
  - 广播纪元：青
  - 掩体纪元：灰紫
  - 银河纪元与归零：银白黑
- **符号语言**：大字号坐标数字做视觉锚点（纪年、光年、维度）；星图与电波波形做 SVG 装饰层；等宽字体用于数据/纪年（科学感）；描边大字纪年做背景装饰层。
- **图片**：横版容器只用横版图、竖版图只进竖版容器（教训清单固化）；占位图与真实图同名替换。

## 六、技术方案

**技术栈**：Astro 5.x 静态生成（零客户端 JS）+ 手写 CSS + JSON 数据源。部署 GitHub Pages（或 Vercel/Cloudflare Pages），零服务器成本。

**数据模型**：

```
content/
├── books.json       # 三部曲：id、书名、简介、封面占位
├── eras.json        # 纪元年表分章：id、名称、纪年范围、主题色、导读、头图
├── events.json      # 时间线条目：id、标题、所属书 bookId、纪元 eraId、
│                    #   纪年、梗概、人物id[]、概念id[]、是否大事件、图片来源
├── concepts.json    # 概念：id、名称、分组、双区块文案（书里怎么讲/科学底子）、
│                    #   关联事件id[]、关联人物id[]、关联概念id[]
└── characters.json  # 人物：id、姓名、身份标签、分组、四段式文案、
                     #   关联事件id[]、关联概念id[]、剧照/占位图
```

关联跳转（事件→人物、事件→概念、人物→概念、概念→概念）全部靠 id 互相引用，构建时自动生成链接。图片路径与 base 前缀一律 helper 化。

**工程资产（复用漫威教训清单）**：

- 共享数据模块（`src/lib/data.mjs`）唯一入口
- 校验脚本：引用完整性 + 唯一性/必填 + **双向链接对称性**校验
- 中文文案一律弯引号「」，标注脚本显式幂等（如做中英对照）
- 占位图生成管线（同名替换接真实图）
- base 路径环境变量注入、canonical 用 origin 拼、敏感文件进 .gitignore

## 七、内容生产流程

AI 辅助流水线（以原著为准）：

1. **事实底稿**：按三部曲顺序提取事件/人物/概念清单（先《三体》→《黑暗森林》→《死神永生》），以原著情节为唯一依据
2. **AI 初稿**：按统一模板批量生成时间线梗概、概念双区块、人物四段式文案
3. **人工审校**：逐条核对事实，重点盯三类高频错误：
   - 情节事实错误（顺序、因果关系、谁做了什么事）
   - 物理学概念表述错误（科学底子板块把科幻当科学说）
   - 书与纪元错位（事件挂错所属书/章节）
4. **图片**：腾讯剧版剧照（第一部可对应角色/场面）+ 科学符号风占位图；来源声明置底

## 八、分期与节奏

| 阶段 | 范围 | 说明 |
|------|------|------|
| M1 · 全量上线 | 全三部曲：时间线全纪元 + 概念册 30–40 + 人物墙 15–25 | 三大页面全功能上线，内容按书分三批灌入（《三体》→《黑暗森林》→《死神永生》），每批过校验 |
| M2 · 打磨 | SEO（favicon/og/逐页描述/canonical/robots/sitemap）、移动端真机复测、中英对照标注、真实图片补充 | 漫威 M2 已验证的打磨项平移 |
| M3 · 持续维护 | 按需补充 | 占位图替换、内容勘误 |

**开发节奏（预估）**：

1. 第 1 周：Astro 项目搭建 + JSON schema 定稿 + 校验脚本 + 时间线页样式（宽屏科学符号排版是全站难点，先攻）
2. 第 2 周：概念册 + 人物墙 + 详情页 + 三者互链
3. 第 3–4 周：内容灌入（三批，AI 初稿 + 人工审校）
4. 第 5 周：视觉精修（章主题色、头图、符号装饰层）+ 部署上线

### 质量门禁（上线前）

- 事实错误零容忍——三体读者考据党多，错一处信任归零
- validate + build 全绿；剧照/占位图路径全部命中
- 移动端排版必测（375px 不破版）
- 图片全部压缩（WebP/SVG），横竖比例不混用
- 零客户端 JS（检查构建产物无 script 标签）
