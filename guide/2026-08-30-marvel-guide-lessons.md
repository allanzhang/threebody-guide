# 漫威图鉴项目 · 经验沉淀：教训与规范

> **用途**：下一个类似项目（纯静态内容站 / Astro + JSON 数据源 / 图片站 / GitHub Pages 部署）开工前先读这份，直接避开已踩过的坑。
> 只整理「教训」和「规范」，不记录过程流水账。

---

## 0. 项目速览（给教训提供上下文）

- **形态**：纯静态 MCU 时序图鉴站 —— Astro 5 + 手写 CSS（零客户端 JS）+ `content/` JSON 数据源 + TMDB 官方 WebP 图片 + GitHub Pages 子路径部署
- **规模**：5 篇章 / 40 电影 + 16 剧集 / 71 人物 / 42 概念 / 176 个静态页
- **选型结论（可复用，不必重新论证）**：内容密集、无需交互的站点，Astro 静态生成 + JSON 数据源 + 原生 CSS 是低维护、构建快、部署简单的最优组合；图片走官方源拉取本地化，不依赖运行时 API。

## 1. 通用雷区（坑 → 规避规范）

### 1.1 数据与内容层

| # | 踩过的坑 | 规避规范 |
|---|---|---|
| 1 | 中文 JSON 文案里误用 ASCII 直引号 `"`，破坏 JSON 结构（**踩过 2 次**，批量修复） | 中文文案引号一律用弯引号「」；改中文 JSON 前自查；坏了用 python regex 批量修 |
| 2 | Astro 构建后用 `new URL()` 相对路径读 JSON 解析失败 | 静态页读 JSON 统一 `process.cwd()` 绝对路径 |
| 3 | 各页面各自读数据，路径/顺序/分组逻辑不一致 | 建共享数据模块（本项目 `src/lib/data.mjs`），所有页面唯一入口 |
| 4 | 校验器只查「引用存在性」不查「双向对称」，31 处电影↔人物链接不对称没被发现 | 校验必须同时查引用完整性 + 双向链接对称性（作品↔人物↔概念↔剧集） |
| 5 | 概念词条的 related 字段混入跨库（人物）id，61 处校验错误 | 跨库引用有独立字段：related 只放同库 id，人物关联放 relatedChars |
| 6 | 标注脚本贪心 replace 把长片名拆坏（「美国队长3：内战」被拆） | 单趟最长匹配：从左扫，命中最长词整体吞掉，不逐词 replace |
| 7 | 危险单字词误伤正文（「王」→「王子/王牌」） | 单字词不进词表，用长词替代（如「卡玛泰姬法师」）或不标 |
| 8 | 标注脚本重跑叠加污染 294 处「中文（英）（英）」 | 内容标注脚本必须**显式幂等**（命中词后检测紧跟「（英文）」则跳过）；重跑后跑污染扫描 |
| 9 | 括号叠加污染「奥创（Ultron）（引发危机）」8 处 | 定期全站扫描 `/（[A-Za-z][^）]{1,40}）（[\u4e00-\u9fff]/g` |
| 10 | 新增集合后漏双向链接（剧集↔人物只建了一边） | 新增数据集合时同步扩 schema，两边字段对称（character.series ↔ series.characters） |
| 11 | 未上映作品先写死内容 | 占位方案：yearLabel 加「· 待上映」+ 写预告与待补全说明，不虚构剧情 |
| 12 | 收录范围反复摇摆（正史/非正史分组） | 业务铁律先行并写进设计文档：收录唯一标准 =「观众能否借此理解背景/关系/时间线」 |

### 1.2 构建与工程层

| # | 踩过的坑 | 规避规范 |
|---|---|---|
| 1 | 卡片内嵌 `<a>` 形成嵌套锚点，浏览器折叠卡片结构 | 链接卡片结构里杜绝嵌套 `<a>`（卡片可点则用整卡 link，内容链接不放卡内） |
| 2 | full-page 截图会把内容压到首尾留白、坐标失真 | 视觉验证用 scrollIntoView + viewport 截图；DOM 结构/顺序用 eval 查 children className，比截图更可靠 |
| 3 | 行高 / 间距混杂（2.0/1.7/1.8 混用）观感乱 | 全局统一排版节奏：正文行高 1.9~1.95，区块间距固定一族（28 / 40px） |
| 4 | 标题字段误含 HTML 标签，前台直接渲染出源码 | 数据字段保持纯文本；渲染标题前文本化 |
| 5 | 改数据不跑校验、改视觉不截图，问题后置 | 数据改动必跑 validate + build；视觉改动必截图双确认（截图模型 + DOM 检查） |

### 1.3 图片与视觉层

| # | 踩过的坑 | 规避规范 |
|---|---|---|
| 1 | 全宽横版容器用竖版海报 cover，横向放大+裁切模糊 | **横版容器只用横版图（backdrop 1280x720）**；竖版图配竖版容器 |
| 2 | 竖版肖像 cover 进全宽横版 hero，只露中间一条 | 竖版图要么换匹配比例横版，要么改布局保持原比例（人物 hero 改左右分栏，肖像固定宽） |
| 3 | 占位图与真实图路径不一致，替换成本高 | 占位图生成管线按「同名文件」输出，替换同名文件即接真实图 |
| 4 | 图片 key / 素材源散落 | 图片统一本地 WebP；拉取脚本固化（images/portraits/backdrops/work-detail/reviews）；key 放 `.env.local` 不入库 |
| 5 | 头图高清但拉伸模糊 | 头图 cover + 遮罩；肖像聚焦人脸 + 左强遮罩；backdrop 从 detail 接口取 |

### 1.4 部署与路径层

| # | 踩过的坑 | 规避规范 |
|---|---|---|
| 1 | GitHub Pages 项目站点在子路径 `/marvel-guide/`，站内根路径链接全 404 | **全站链接统一加 base 前缀**：链接/图片/nav/favicon/og 全部 helper 化，不许裸写绝对路径 |
| 2 | canonical 用 SITE_URL 拼出现双 base | canonical 用 `Astro.url.origin` 拼（SITE_URL 含路径时会双 base） |
| 3 | 全局 git 配置死代理，SSL 全部失败 | 代理用环境变量注入，别写进全局 git 配置 |
| 4 | 本地 / 线上环境差异导致路径错 | SITE_URL / BASE_PATH 用环境变量注入，本地默认 example.com / `/` |
| 5 | 敏感信息 / 构建产物误入库 | `.gitignore` 锁死 `.env.local` / dist / 本地记忆目录 / sitemap 产物 |

### 1.5 协作与流程层

| # | 踩过的坑 | 规避规范 |
|---|---|---|
| 1 | 范围扩大失控 | 每轮只做已确认范围；新问题先报告，由用户拍板再动 |
| 2 | 用户反馈多轮聚焦不清 | 每轮只处理一个用户反馈点：问题→根因→方案→验证，闭环后再下一个 |
| 3 | 术语口径不一、结论丢失 | 文档单一术语口径；待确认清单与已确认结论分离，结论回填对应章节 |
| 4 | 数据量大时人工校验漏 | 脚本兜底优先：校验 / 标注 / 对称扫描全部脚本化，人工只做主观看板 |

## 2. 下一项目直接照做的规范 Checklist

开工前逐条打勾：

- [ ] **立项**：先写设计文档并确认（定位/范围/分期），再动手；内容型与工程型任务分开列
- [ ] **数据层**：共享数据模块唯一入口；JSON 中文用弯引号「」；validate 必含引用完整性 + 双向对称扫描
- [ ] **图片层**：横版容器只配横版图，竖版图只进竖版容器；占位→真实图同名替换；图片 key 不入库
- [ ] **标注层**：单趟最长匹配词表；分字段词表（专名 / 正文 / 纯中文保持）；显式幂等；重跑后跑污染扫描
- [ ] **部署层**：base 路径环境变量注入；全站链接 helper 化；canonical 用 origin；代理环境变量化；敏感文件进 .gitignore
- [ ] **验证层**：数据改动 → validate + build；视觉改动 → viewport 截图 + DOM 检查；上线前真机复测移动端
- [ ] **协作层**：先确认后动手；每轮聚焦一个反馈；结论回填文档；落盘提醒

## 3. 可复用资产清单（从本项目直接搬）

| 资产 | 用途 |
|---|---|
| `scripts/validate-content.mjs` | 引用完整性 + 唯一性/必填 + 双向链接校验 |

| `src/lib/data.mjs` 内 linkConcepts | 正文概念/电影名自动内联链接（只链概念名，人物走 chip） |

## 附：本项目踩坑次数 Top 雷区（优先级提示）

1. **图片比例错配**（横版容器配竖版图）— 三次返工，视觉问题最高频
2. **JSON 引号 / 标注叠加污染** — 反复出现，必须靠脚本兜底
3. **子路径链接** — 上线后才发现，全站链接 helper 化一次性根治
4. **双向链接不对称** — 校验器升级后根治
