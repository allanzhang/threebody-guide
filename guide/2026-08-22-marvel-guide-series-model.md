# 漫威图鉴 · 剧集入主线数据模型设计（M2）

- **日期**：2026-08-23
- **状态**：设计已确认，待实施（并入 M2）
- **决策来源**：用户明确「重要剧集与电影同级别」并点名《神盾局特工》；随后纠正判断标准——**收录与否不取决于"是否 MCU 正史"，而取决于"观众是否需要它来理解背景信息、人物关系、时间线"**
- **统一原则**：本站面向非漫威迷，判断一部剧要不要收录、怎么呈现，唯一标准是"它是否帮助观众理解背景信息 / 人物关系 / 时间线"。不按正史/非正史设硬性分组。

## 一、核心决策

1. **剧集与电影同级**：剧集不是「辅助关联层」，而是 MCU 主内容，纳入主时间线。
2. **收录判据（按需全收）**：凡有助于观众理解人物关系、背景设定、时间线衔接的剧集都收入主线；无关紧要的（如短片《我是格鲁特》）可收录也允许省略。
3. **粒度**：每部剧集在时间线占 **1 个条目**，用季数范围标注，不做分季/分集。
4. **呈现方式（补全背景）**：每部剧条目不仅写剧情梗概，还要专门补全——**背景信息**（它发生在主线的哪个位置）、**人物关系**（它串起/解释了哪些人物）、**时间线衔接**（观众带着它去看哪部后续电影/剧集能更懂）。用 `backgroundNote` / `relationsNote` / `timelineNote` 三段补充，或合并为一段「*观众须知*」。
5. **时间线衔接**：按剧情时序将剧集插入对应篇章（`eraId`），用衔接注释说明它和主线的关系（如"可作为《复仇者联盟4》后的支线，帮助理解灭霸响指对普通人的影响"）。
6. **数据结构**：新增 `content/series.json` 集合，与 `movies.json` 并列，不混入电影文件。

## 四、时间线页面适配

1. **type 徽标**：剧集条目用「剧集」+ 季数（S1–S7）标识，电影无此徽标。
2. **按剧情时序混排**：剧集按剧情发生的时间插入对应篇章（`eraId`），与电影同列，不单独隔离。
3. **观众须知板块（核心呈现）**：每个剧集条目除剧情梗概外，突出「观众须知」区，含三要素：
   - *背景*：发生在主线的哪个位置（如"紧随《复仇者联盟4》之后"）
   - *人物关系*：串起/解释了哪些人物（如"解释旺达为何成为绯红女巫"）
   - *时间线衔接*：观众看完后续哪部更懂，或补哪段主线缺口
4. **独立属性标注**：对时间线相对独立、不看也不影响主线的剧集（如神盾局特工），用轻量文字标注"本剧背景补充型，不影响主线理解"，而非隔离分组。
5. **人物联动**：剧集引入的新角色补入人物墙，并在其详情页标注来自的剧集。

## 五、与现有功能衔接

- **经典台词**：核心主线剧集优先补 quotes。
- **中英对照**：新增剧集名词跑 `annotate-terms.mjs`。
- **校验器**：扩展支持 `series.json` 的 id 校验与双向链接（series.characters ↔ character 的引用对称）。
- **数据一致性**：series 与 characters 互链，沿用现有双向链接检查。
